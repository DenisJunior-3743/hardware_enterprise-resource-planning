🗄️ 3. Database Design (THIS IS THE HEART)
Let me give you a clean, normalized structure.
________________________________________
👤 Users Table
users (
  user_id INT PRIMARY KEY AUTO_INCREMENT,
  username VARCHAR(50),
  email VARCHAR(100),
  password VARCHAR(255),
  role ENUM('admin', 'user'),
  created_at TIMESTAMP
)
________________________________________
📂 Categories Table
categories (
  category_id INT PRIMARY KEY AUTO_INCREMENT,
  name VARCHAR(100),
  created_at TIMESTAMP
)
________________________________________
📦 Items Table
items (
  item_id INT PRIMARY KEY AUTO_INCREMENT,
  category_id INT,
  name VARCHAR(100),
  description TEXT,
  price DECIMAL(10,2),
  stock_quantity INT DEFAULT 0,
  restock_level INT DEFAULT 20,
  created_at TIMESTAMP,
  FOREIGN KEY (category_id) REFERENCES categories(category_id)
)
________________________________________
🛒 Sales Table (Main Transaction)
sales (
  sale_id INT PRIMARY KEY AUTO_INCREMENT,
  total_amount DECIMAL(10,2),
  sale_date TIMESTAMP,
  user_id INT,
  FOREIGN KEY (user_id) REFERENCES users(user_id)
)
________________________________________
🧾 Sale Items Table (VERY IMPORTANT)
👉 This is where most students mess up.
sale_items (
  sale_item_id INT PRIMARY KEY AUTO_INCREMENT,
  sale_id INT,
  item_id INT,
  quantity INT,
  price DECIMAL(10,2),
  subtotal DECIMAL(10,2),
  FOREIGN KEY (sale_id) REFERENCES sales(sale_id),
  FOREIGN KEY (item_id) REFERENCES items(item_id)
)
________________________________________
📥 Restocks Table
restocks (
  restock_id INT PRIMARY KEY AUTO_INCREMENT,
  item_id INT,
  quantity INT,
  restock_date TIMESTAMP,
  user_id INT,
  FOREIGN KEY (item_id) REFERENCES items(item_id),
  FOREIGN KEY (user_id) REFERENCES users(user_id)
)
________________________________________
📊 Optional: Activity Logs (VERY SMART FOR ERP)
logs (
  log_id INT PRIMARY KEY AUTO_INCREMENT,
  action TEXT,
  user_id INT,
  created_at TIMESTAMP
)
________________________________________
⚙️ 4. Key System Logic (Don’t Miss This)
🔹 When recording a sale:
•	Insert into sales
•	Insert multiple rows into sale_items
•	Deduct stock:
stock_quantity = stock_quantity - quantity
________________________________________
🔹 When restocking:
•	Insert into restocks
•	Increase stock:
stock_quantity = stock_quantity + quantity
________________________________________
🔹 Low stock alert:
WHERE stock_quantity <= restock_level

🚀 TECHNICAL PROMPT
Build a modular web-based ERP system for a hardware inventory and sales management system using:
•	Frontend: HTML5, CSS, Bootstrap, JavaScript, jQuery
•	Backend: PHP (procedural or MVC) with AJAX
•	Database: MySQL
Core Requirements:
1.	Authentication System
o	User registration, login, logout
o	Password hashing
o	Session management with auto logout on inactivity
2.	Inventory Management
o	CRUD operations for categories
o	CRUD operations for items under categories
o	Each item must include:
	Name, category_id, price, stock_quantity, restock_level
3.	Sales Module
o	Ability to create a sale transaction
o	Select multiple items with quantities (cart-like system)
o	Store sales in:
	sales table (main transaction)
	sale_items table (line items)
o	Automatically deduct stock after sale
4.	Restock Module
o	Record restocking transactions
o	Increase stock quantities
o	Maintain restock history
5.	Dashboard & Analytics
o	Display:
	Daily, weekly, monthly sales
	Total revenue
	Low stock alerts
o	Use charts (line & bar graphs)
6.	Reports
o	Filter by:
	Date range
	Item
	Category
o	Generate printable reports
7.	UI/UX Requirements
o	Sidebar navigation with collapsible menus
o	Mobile-first responsive design
o	Large buttons for usability (age 40+ users)
o	Confirmation dialogs for destructive actions
o	Undo support where possible
8.	System Behavior
o	All data views must support filtering
o	Use AJAX for dynamic updates (no full page reloads)
o	Maintain clean separation of concerns (PHP, JS, CSS)
9.	Database Integrity
o	Use foreign keys
o	Normalize tables (avoid redundancy)
o	Ensure transactional consistency for sales
